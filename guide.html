事業場ノート / VERSION 1.0

導入・操作ガイド

地域・事業場・機器台帳・タスクを管理する、個人用のアプリです。
スマホとパソコンで共有し、電波がない現場でも記録できます。

まず知っておくこと

アプリ本体は完成しています。自動共有を使うには、ご本人のSupabaseアカウントと最初の接続設定が必要です。この配布物には、顧客情報・パスワード・接続先は入っていません。

役割使うもの
アプリを開く場所GitHub Pages。ご希望どおり、GitHubにファイルを置きます。
2台のデータ共有Supabase。ログインした本人の記録・添付ファイルを保管します。
電波がない時の保存スマホやパソコンのブラウザ内。接続が戻り、アプリを開くと送信します。

接続前は「お試しモード」となり、その端末だけで動作します。お試しデータは、バックアップしてログイン後に復元することで共有できます。

STEP 01

GitHubにアプリを置く

  1. 受け取ったZIPを右クリックし、「すべて展開」で解凍します。
  2. GitHubにログインし、新しいリポジトリを作成します。名前の例は hoan-note です。無料プランでGitHub Pagesを使う場合は、公開用のリポジトリを選びます。
  3. 解凍したフォルダの app フォルダを開き、その中身をアップロードします。app フォルダそのものを入れるのではありません。index.html がリポジトリの一番上にある状態にします。icons と vendor と setup のフォルダも一緒に入れます。
  4. リポジトリの Settings → Pages を開きます。Source：Deploy from a branch、Branch：main、フォルダは / (root) を選び、Saveします。
  5. 公開が終わると、Pagesの画面にURLが表示されます。例：https://ユーザー名.github.io/hoan-note/。そのURLをChromeで開いてください。
公開するのはアプリ本体です。バックアップZIPや、業務の写真・PDFをGitHubへアップロードする必要はありません。業務データはアプリから登録します。

パソコン内のindex.htmlをダブルクリックする方法では、保存・オフライン機能が正しく動作しません。GitHub PagesのhttpsのURLで開いてください。新しい空のリポジトリでは、ファイルの追加画面に「uploading an existing file」というリンクが出る場合があります。

STEP 02

データの共有先を作る

① Supabaseのプロジェクトを作成

  1. Supabaseでご本人のアカウントを作成します。
  2. 新しいプロジェクトを作ります。名前は例として hoan-note。地域はTokyoなど近い地域を選びます。まずはFreeプランで開始できます。
  3. プロジェクト作成時のデータベースのパスワードは保管します。これは、後でアプリに入れるログインパスワードとは別です。

2026年9月26日に確認したFreeプランは、データベース500MB・ファイル1GBなどの上限があり、1週間利用がないとプロジェクトが休止します。容量と利用状況を確認しながら試してください。有料契約はこの作業では行っていません。最新の条件は料金ページで確認できます。

② データベースの初期設定

  1. Supabaseのプロジェクトで SQL Editor を開き、新しいクエリを作ります。
  2. 配布フォルダの app/setup/01-database.sql をメモ帳で開き、内容をすべてコピーします。このリンクから開くこともできます。
  3. SQL Editorへ貼り付けて Run を押します。正常終了すれば、記録用の表・本人確認のルール・写真用の非公開保管場所が作られます。

③ アプリ用の利用者を作成

  1. Authentication → Users を開き、利用者の追加（Add user / Create new user）を選びます。
  2. ご自身のメールアドレスと、アプリ用に決めたパスワードを入力します。メール確認済みにする Auto Confirm User の選択がある場合は有効にします。
  3. Authenticationの設定で、一般の新規登録を許可する Allow new users to sign up をオフにします。匿名ログインも有効にしません。このアプリには新規登録の画面はありません。

④ 本人として登録

  1. app/setup/02-owner.sql をメモ帳で開き、全体をコピーしてSQL Editorに貼り付けます。このリンクから開くこともできます。
  2. SQL Editor上で、ここに自分のメールアドレス を、③で登録したメールアドレスに置き換えます。前後の ' は残します。
  3. Run を押します。これで、その利用者だけがアプリのデータを扱えるようになります。GitHub上のファイルを書き換える必要はありません。

⑤ 接続に使う2つの情報を控える

プロジェクトの Connect、または Settings → API Keys から、Project URL と Publishable key を控えます。

使うもの形式
Project URLhttps://…supabase.co
Publishable keysb_publishable_… で始まるキー
sb_secret_… で始まるSecret key、service_roleキー、データベースのパスワードは、アプリへ入力しません。チャットに送る必要もありません。
STEP 03

パソコンとスマホを接続

  1. パソコンのChromeで、GitHub Pagesに公開したアプリを開きます。
  2. 設定 → 接続設定・ログイン を開きます。
  3. Project URL、Publishable key、登録した利用者のメールアドレス、アプリ用パスワードを入力し、「接続してログイン」を押します。
  4. 右上が「同期済み」になることを確認します。
  5. Pixel 9aのChromeでも同じURLを開き、同じ設定・メールアドレスでログインします。再度「同期済み」を確認します。
  6. スマホのChromeメニューから「ホーム画面に追加」または「アプリをインストール」を選ぶと、通常のアプリのように開けます。
最初は仮の事業場で確認

パソコンで地域とテスト用事業場を1件登録 → スマホで表示されることを確認 → スマホを機内モードにしてタスクを追加 → 機内モードを解除してアプリを開く → パソコンにも追加されることを確認してください。両端末とも、アプリを開いていれば通常15秒以内に同期確認が始まります。通信が弱い場合や添付が多い場合は時間がかかります。

初回ログインや、まだ受け取っていない写真の取得には通信が必要です。外出前に、両端末で「同期済み」、設定で「オフライン利用の準備済み」になっていることを確認してください。

入力項目について

追加できる形式は、1行テキスト・複数行テキスト・数値・日付・日時・選択肢です。項目名、必須指定、選択肢、表示順を変更できます。名前の項目は一覧表示に必要なので削除できません。登録済み項目の入力形式を変えたい場合は、新しい項目を追加します。

項目の削除は非表示として扱い、過去の値は残します。「削除済みの項目」から戻せます。進捗の「完了」は未完了数を数える基準なので、完了として扱う選択肢はこの表記を使ってください。

写真・PDFについて

JPEG・PNG・WebP・GIF・PDFに対応し、1ファイル20MBまでです。写真を自動で縮小しないため、銘板の細かな文字も元の解像度で保管します。容量を抑えたい場合は、登録前に写真を縮小してください。PDFの内蔵表示が使えない機種では「端末に保存」から開けます。

両方の端末で同じ記録を変更したとき

上部に「要確認」が表示されたら、両方の内容を比較して採用する方を選びます。勝手に片方を上書きしません。両方の文面が必要な場合は、選択前に控えてから採用後の記録に追記してください。同じ記録の異なる項目でも、同時編集時は確認が必要になる場合があります。

バックアップと復元

  1. オンラインで同期を完了します。
  2. 設定 → バックアップを保存を押します。
  3. ダウンロードされたZIPを、パソコンなどご自身の保管先に保存します。

バックアップには、入力した記録、共通項目の設定、ごみ箱内の記録、写真・PDFが含まれます。ログインパスワード・認証情報は含めません。未取得の添付ファイルがある場合は、欠けたままのバックアップを作らず、先に同期するよう案内します。

復元は「設定 → 復元する」からZIPを選びます。同じIDの記録はバックアップの内容で上書きし、それ以外の記録は残します。ログイン中に復元した変更は、共有先にも同期します。

端末内の記録とバックアップは、このアプリ独自の暗号化を行っていません。バックアップZIPを公開用のGitHubへ置かず、個人用の保管先に保存してください。写真が多い場合のバックアップ作成・復元は、空き容量のあるパソコンで行ってください。復元ファイルは1GBまでです。

ごみ箱は復元のため、写真の原本を残す設計です。削除だけでは共有先の使用容量は減りません。容量整理が必要になったら、記録との対応を保った整理方法を追加してから行ってください。

困ったとき

表示・状況確認すること
お試し・端末内のみまだ共有先にログインしていません。「接続設定・ログイン」を開いてください。
利用者登録が未完了Supabaseで本人の利用者を作り、02-owner.sqlを実行したか確認します。
共有先の初期設定が未完了01-database.sqlが全体として正常に実行されたか確認します。
ログインの期限が切れた設定から同じアカウントで再ログインします。端末内の記録は残ります。
共有待ちが消えない通信、Supabaseの休止・容量を確認し、「今すぐ同期」を押します。休止している場合はSupabase側で再開してください。
オフラインで開けないオンラインで同じURLを開き直し、設定に「オフライン利用の準備済み」が表示されることを確認します。シークレットモードは避けてください。
写真が別の端末で開けない元の端末でアップロード、新しい端末でダウンロードが完了するまでオンラインでアプリを開きます。
記録が消えたように見える同じ公開URL、同じアカウント、同じブラウザのプロファイルか確認してください。ごみ箱も確認します。

アプリを閉じている間は同期しません。オフライン中にスマホを紛失したり、ブラウザのデータを削除した場合、その端末だけに残っていた未送信分は復元できません。
