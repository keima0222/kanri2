# 事業場ノート 1.0.0

最初に `START.html` を開いてください。日常利用のために開発ツールをインストールする必要はありません。

## 配布物

- `app/`：GitHub Pagesへ公開する全ファイル。ソースコードを含みます。
- `app/guide.html`：日本語の導入・操作ガイド。
- `app/setup/01-database.sql`：専用Supabaseプロジェクトの初期設定。
- `app/setup/02-owner.sql`：ご本人を許可する設定のひな形。
- `検証結果.md`：確認した動作と未実施の確認。
- `画面例/`：架空のデータを使った動作確認時の画面。
- `tests/`、`package.json`：開発者向けの検証コード。

公開するのは `app` フォルダの**中身**です。バックアップZIPや顧客情報をリポジトリに入れないでください。

## 実装概要（開発者向け）

ビルド不要のHTML/CSS/JavaScript。ハッシュ形式の画面遷移を使用し、GitHub Pagesのリポジトリ配下のURLにも対応します。PWAの公開用ファイルだけをService Workerでキャッシュします。認証通信や業務データはCache APIに保存しません。

- IndexedDB：記録とBlobを保存。利用者ID・プロジェクトURL・アプリの公開パスごとに保存領域を分離。
- Supabase Auth：メールとパスワードによるログイン。パスワードは保存せず、セッショントークンを端末に保持。
- Supabase PostgreSQL：本人の許可リスト、RLS、バージョン検査を行うRPCで記録を同期。
- Supabase Storage：非公開バケット `hoan-assets`。利用者IDのパスに所有者だけがアクセス可能。
- 自動同期：保存後、通信復帰時、アプリ再表示時、表示中の15秒周期。バックグラウンドでの常時同期ではありません。
- 差分取得：利用者単位で書き込みを直列化し、コミット順序を保ったリビジョンから500件ずつ取得します。
- 競合：レコード単位の版照合。端末内とクラウドの両方の変更を保持し、本人の選択後に解消。
- 再送：mutation IDとサーバー側の受領記録で二重反映を防止。
- 削除：論理削除。親を削除したときは子の表示を抑止し、復元できる状態を維持。
- バックアップ：ZIP内にJSONと原本Blobを格納。復元前に関連付け、型、ファイルのSHA-256を検査し、ローカルDBへの書き込みを1トランザクションで実行。

共有先のアカウント・利用者登録は未設定です。本番環境への初回接続と受け入れ確認は導入ガイドに沿って行います。

## 検証コードの実行

開発者向けです。Node.jsとnpmを用意し、このREADMEとpackage.jsonがあるフォルダで実行します。

```sh
npm install
npx playwright install chromium
npm test
npm run test:database
```

ブラウザテストは終了時に停止するローカルHTTPテスト用サーバーを起動します。外部サービスの認証情報は使いません。実行結果は `test-results/` に保存します。任意のChromium実行ファイルを使う場合は `HOAN_TEST_CHROME` を指定できます。

SQL検証はPGliteのPostgreSQLを使用し、Supabase固有のAuth・Storageスキーマはテスト用の最小構成で代用します。実サービスへの接続確認を置き換えるものではありません。

## 更新時

アプリファイルを更新したら `app/sw.js` のVERSIONを必ず変更し、`app/model.js` の表示用バージョンも更新します。Service Workerは利用者が更新ボタンを押すまで新しい版への切り替えを待ちます。既存データを壊すスキーマ変更は別途移行処理を作成してください。

`hoan_receipts`は再送の安全性のために保持します。将来の容量整理では、未送信の端末や古いバックアップとの整合性を設計してから期限を決めてください。添付ファイルも、ごみ箱からの復元用に原本を保持します。

## 外部ライブラリ

配布するブラウザ用ライブラリはJSZip 3.10.1です。ライセンスは `app/vendor/JSZip-LICENSE.md` に含まれます。実行時にCDNからJavaScriptを取得しません。
